## Introduction

This post explores a refinement test of an existing n8n blog post PR workflow. The focus is on improving preview-only mode, rigorous input validation, and ensuring that pull requests create safe, draft-only blog content. The goal is to enhance automation without sacrificing the human review and manual publishing steps that keep the process reliable and high quality.

## Why Hardening Matters

Automations that write and submit content carry risks when they act beyond drafts. A key lesson is to always treat generated content as a starting point. This means:

- Creating content with `status: "draft"` so it does not publish right away.
- Opening GitHub PRs for manual review before publishing.
- Validating inputs to prevent malformed or vague posts.
- Generating social and image assets alongside drafts, but without auto-posting.

These constraints help maintain trust and editorial control while reducing repetitive work.

## Workflow Refinements

The key improvements tested here include:

- **Preview-only mode:** The system simulates the entire content generation and PR creation without pushing to the main branch, allowing full review before any public changes.
- **Input validation:** The trigger now stops and returns clear errors if essential fields like topic, category, or language are missing or invalid.
- **Draft-first enforcement:** Every blog post starts explicitly as draft to prevent accidental publishing.
- **Separation of concerns:** The workflow generates the blog draft, social media pack, and image prompts as distinct, reviewable assets in the same PR.
- **Consistent file naming:** Slugs and filenames follow strict kebab-case and include timestamps for version clarity.

## Implementation Notes

This workflow integrates deeply with the existing Next.js + MDX system for the site. Key technical points:

- Blog drafts are saved to `content/posts/` with strict frontmatter including draft status.
- Social packs can be optionally generated but remain in draft until reviewed.
- Image prompts follow the black, white, and orange developer lab aesthetic with no automatic image generation in MVP.
- Generated content avoids raw HTML or complex JSX, focusing on stable MDX.
- The PR branch uses a descriptive name aligned with the post slug and timestamp.
- Automated steps create commits and PRs but do not merge or modify live content until reviewed by Javier.

## Result

The hardened workflow reduces risk and improves feedback loops. Reviewers can safely inspect all generated content in the PR, suggest edits, and control what goes live. Errors or incomplete inputs are caught early, preventing wasted cycles.

Generating social content and image prompts alongside the draft provides a more complete package for review and easier repurposing after publication.

## Next Steps

- Expand validation with schema checks for frontmatter and body content.
- Explore optional MDX component generation for richer posts.
- Later phases may add image generation triggered only after editorial approval.
- Consider monitoring and alerting on PR health and review status to accelerate publishing.
- Continue refining the balance between automation leverage and manual quality control.
